# Repository Hygiene — What Never Enters Git (SB-002, PRD §4 "Safe by Design")

SecureBank is a security-training platform: an accidentally-committed real
secret here is a worse outcome than in most repos, because the audience is
specifically people practising finding exactly that class of mistake
(`DEVSECOPS-01`'s scenario is literally a committed API key). `.gitignore`
at the repo root is the enforcement mechanism; this doc explains the
categories behind it so a future addition to `.gitignore` follows the same
reasoning instead of being copy-pasted from an unrelated project.

## Categories, and where each is enforced

| Category | Pattern(s) in `.gitignore` | Why |
|---|---|---|
| Dependency trees | `node_modules/` | Regenerated from `package-lock.json`; never hand-edited, never committed |
| Build output | `dist/`, `build/`, `apps/web/.next/`, `.turbo/`, `.vercel/`, `*.tsbuildinfo` | Regenerated by `npm run build`; committing it causes stale-artifact bugs |
| **Real environment variables** | `.env`, `.env.local`, `.env.*.local` (with `!.env.example` as the one exception) | `services/api/.env` holds `DATABASE_URL`, `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET` for *your* machine. `.env.example` files (committed, no real values) are the template every contributor copies |
| **Secrets/credentials in any other form** | `*.pem`, `*.key`, `*.crt`, `*.p12`, `*credentials*.json` | Catches the shapes real secrets usually take even outside a `.env` file (TLS keys, service-account JSON, etc.) |
| Local databases | `services/api/*.sqlite`, `*.sqlite3` | Defensive — the project uses Postgres via Docker, not SQLite, but a local experiment shouldn't leak in either |
| Logs / caches | `*.log`, `logs/`, `.eslintcache`, `coverage/` | Machine- and run-specific, not meaningful to anyone else's checkout |
| Editor/OS artifacts | `.DS_Store`, `.vscode/`, `.idea/`, `*.swp` | Personal tooling state, not project configuration |
| Design source files | `design_handoff_securebank/` | The design handoff's raw prototype (`SecureBank.dc.html`, `support.js`, screenshots) is a reference asset the team was given, not application source — kept out of the app repo's history by request |

## What this means in practice

- If you add a new integration that needs a secret (an SMS provider API key,
  a cloud credential), add the **name** to `services/api/.env.example` with
  a placeholder value, and only the real value to your local `.env`. Never
  the reverse.
- Before `git add -A` or any broad staging command, run `git status` and
  actually look at the list — `.gitignore` catches known shapes, not
  everything. A secret pasted directly into a `.js` file it doesn't catch by
  filename.
- If a secret is committed by mistake, `.gitignore` alone does not fix it —
  the value is already in git history. Rotate the credential and follow the
  project's incident process; do not just delete the file in a new commit
  and consider it resolved.
